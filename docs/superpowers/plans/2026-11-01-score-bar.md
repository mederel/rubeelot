# Score Bar (US-096) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One sticky score bar, shown for the whole game in bot games, private tables and pass-and-play, replaces the three scattered scoreboards.

**Architecture:** A pure module `score-bar.js` turns `match`/`board` data into a model and a screen-reader sentence. A single `#score-bar` element in `index.html` is filled by `showScoreBar` in `app.js`, called from the three render paths that today write scoreboards. Frontend only.

**Tech Stack:** Vanilla JS in `crates/beelot-server/static/`, Node `node:test` for pure modules, Playwright MCP for browser checks.

**Spec:** `docs/superpowers/specs/2026-11-01-score-bar-design.md`

## Global Constraints

- Frontend only: no server, API or dependency change, no new Settings option.
- The count-up animation is NOT in this story (US-091); numbers are set directly.
- The contract is not shown in the bar (US-099 shows it at the seat).
- Phone bar height ≤ 64 px at 390 × 844 (two lines, breakpoint ≤ 600 px); it never hides the hand or the seats.
- Live region: `role="status" aria-live="polite"`; rewritten only when the sentence changes; round points are never announced.
- "My team" is marked by the word "You" plus an outline, not by colour alone.
- New texts translated into French (`i18n.js`) and Dutch (`i18n-nl.js`); use "bot", not "AI".
- Honour the effects level (US-094): no transitions at Off.
- Project checks: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --workspace` (Docker running), plus `node --test crates/beelot-server/frontend-tests/`.

## Review Focus

- A snapshot with no `match` (bidding in some modes): the bar stays hidden, never shows `undefined` or `NaN`. Test: Task 1 `null match`; browser in Task 2.
- A completed match: final scores stay, no round points confusion. Test: Task 1 `complete match`.
- Scores of 1,000+ and 10,000+: grouped with the page language, not raw digits. Test: Task 1 announcement test with a formatter.
- A viewer on an odd seat (East–West) and pass-and-play switching viewers: "You" lands on the right team. Test: Task 1 `myTeam` cases; browser pass-and-play in Task 2.
- Many quick updates during play (every trick, bot reveals): the live region speaks only on a match-score change. Test: Task 2 browser accessibility check.
- Leaving a game (home, history, another table) then opening one: no stale scores flash. Test: Task 2 browser.

### Task 1: The pure module `score-bar.js`

**Files:**
- Create: `crates/beelot-server/static/score-bar.js`
- Test: `crates/beelot-server/frontend-tests/score-bar.test.cjs`

**Interfaces:**
- Produces:
  - `scoreBarModel({ match, board, myTeam }) -> null | { teams: [Team, Team], target: number, complete: boolean }` where `Team = { name: "North–South" | "East–West", matchScore: number, roundPoints: number | null, mine: boolean }`; index 0 is North–South, 1 is East–West. Returns `null` when `match` is null/undefined. `roundPoints` comes from `board.northSouthScore` / `board.eastWestScore`, `null` when `board` is null/undefined. `mine` is true for the team equal to `myTeam` (0, 1, or `null` for none). `matchScore` from `match.northSouth` / `match.eastWest`, `target` from `match.target`, `complete` from `Boolean(match.complete)`.
  - `scoreBarAnnouncement(model, t, format) -> string` — `t` is the translate function, `format` formats numbers. English source text: `"Match score: North–South {0}, East–West {1}, to {2}."` passed through `t(key, a, b, c)` in the same way `t` is used in `app.js`, with team names not interpolated (the key keeps them) and numbers passed through `format`. Round points are not included.
  - Ends with `if (typeof module !== "undefined") module.exports = { scoreBarModel, scoreBarAnnouncement };` like `contract-badge.js`.

- [ ] **Step 1: Write the failing tests** in `score-bar.test.cjs` (require `../static/score-bar.js`). Tests, each asserting with `assert.deepEqual`/`assert.equal`:
  - `no match gives no model`: `scoreBarModel({ match: null, board: null, myTeam: 0 })` is `null`; same for `undefined`.
  - `auction has no round points`: match `{northSouth: 420, eastWest: 310, target: 1000}`, `board: null` → both `roundPoints` are `null`, scores 420/310, target 1000, `complete: false`.
  - `play shows round points`: board `{northSouthScore: 62, eastWestScore: 35}` → `roundPoints` 62 and 35.
  - `my team`: `myTeam: 0` marks only North–South; `1` only East–West; `null` neither.
  - `complete match`: `match.complete: true` → `complete: true`.
  - `announcement`: with `t = (key, ...a) => key.replace(/\{(\d)\}/g, (_, i) => a[i])` and `format = (n) => n.toLocaleString("en")`, a model with scores 10420 / 310 and target 1000 gives `"Match score: North–South 10,420, East–West 310, to 1,000."`; the sentence never contains round points (use round points 62 and assert the text does not include `62`).
- [ ] **Step 2: Run** `node --test crates/beelot-server/frontend-tests/score-bar.test.cjs`. Expected: FAIL (module not found).
- [ ] **Step 3: Implement** both functions in `static/score-bar.js` per the Interfaces block, with a header comment in the style of `contract-badge.js`.
- [ ] **Step 4: Run** the same command. Expected: all PASS.
- [ ] **Step 5: Commit** `feat: model the score bar (US-096)`.
